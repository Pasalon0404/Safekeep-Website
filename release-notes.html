What’s new in SafeKeepVault

Release Notes

A plain-English summary of each release. The full notes, files and checksums are on the GitHub releases page.

v1.47 — October 19, 2026

SafeKeep can now update itself from a signed file, without reflashing and without touching your vault. Getting there takes one last reflash, onto a flash drive of 8 GB or more.

  • Update SafeKeep — a new section in Device Options. Copy a signed update file onto the Transfer Drive, click Check for update, then Install and Restart now. SafeKeep installs it only if it carries the maintainer’s signature, checked against the key built into the stick, and only if it is newer than what you’re running. Before installing it shows the version, the build stamp and the app’s SHA-256, to compare with the release on GitHub. The first update file will come with v1.48.
  • Two copies of the system — the stick now holds two copies of SafeKeep’s operating system. An update is written into the spare copy and checked before it is switched on, so a power cut or a bad file never leaves a stick that won’t start. The version you updated from stays available as previous version in the start-up menu.
  • 8 GB flash drives — the two copies and a Transfer Drive big enough for an update file (now 2.5 GB) need a flash drive of 8 GB or more. The download is still about 1.3 GB.
  • One last reflash — sticks set up with v1.46 or earlier can’t update in place. Back up, flash v1.47 and restore once, as the update guide explains. If your stick is smaller than 8 GB, flash v1.47 onto a new one.
  • A sound for each QR code read — every scanner in the app plays the soft tick of the hover sound when it reads a QR code, and again for each new frame of an animated QR, so you can hear a transaction coming in. It follows the sound settings in Device Options.
  • Check Verifiable Dice on Ian Coleman’s tool — the Verifiable Dice panel explains how: choose entropy type Base 10 (its Dice type counts a 6 as 0 and gives different words) and the same word count. Do this only with practice rolls, or with the tool’s offline copy on a computer that never goes online again.

v1.46 — October 17, 2026

The PSBT Signer now checks every transaction against the wallets you own and shows exactly what it spends, and a mistyped passphrase can no longer slip through.

  • Saved wallets — in the Output Descriptor tool, Save to Vault keeps a wallet’s watch-only descriptor in the encrypted vault, with a name you choose. The PSBT Signer then says which of your wallets a transaction spends from, and warns when an input matches none of them. It works this out itself from the descriptor and never takes the PSBT’s word for it.
  • Change you no longer have to check by hand — when a change output is one of your saved wallet’s own addresses, it is verified, even in PSBTs that leave out the multisig details (for example BlueWallet’s compact QR exports). A payment to another of your own wallets still needs its checkbox.
  • What the transaction does — the review starts with a summary: how much you are sending, the mining fee, the total leaving your wallet, and the change coming back. Below it, the inputs being spent, with each one’s amount, address, saved wallet and, for multisig, how many signatures it has so far.
  • Lock time and replace-by-fee — the review shows whether the transaction can’t be mined before a block or date, and whether its fee can be raised later. An input that is time-locked (for example an inheritance or recovery path) gets a warning.
  • Compare with the address you were given — each payment card has a box to paste or scan the address the recipient gave you. SafeKeep compares every character: “Identical”, or “Different address. Don’t sign” with the differences highlighted. You still tick the box yourself.
  • Fees for older addresses — spending from legacy 1… addresses now shows the mining fee and fee rate instead of “unknown”. SafeKeep checks that the previous transaction a PSBT includes really is the one being spent. A PSBT that fails this check could hide part of the fee, so signing it is blocked.
  • Type your passphrase twice — a typed BIP-39 passphrase must be typed again before the Dashboard applies it or the Output Descriptor tool uses it. A typo would open a different, empty wallet or hand your cosigners the wrong key. In multisig, Key 1 stays hidden until it’s confirmed. Passphrases loaded from the Passphrase Library don’t need retyping.
  • Auto-Off — a third idle timer in Device Options powers SafeKeep off after a set number of idle minutes (default 30, 0 = stay on), with a 60-second warning. It also applies at the password prompt.
  • Shamir recovery shows both readings — recovering SLIP-39 shares shows the wallet as made with SafeKeep and as made on a Trezor, each with its fingerprint and first address. Only Restore This Wallet (made with SafeKeep) saves anything, so a Trezor share set is never saved as the wrong wallet.
  • Verify reads wallet exports — Check Descriptor also takes BlueWallet and Coldcard multisig setup files, BSMS records, Sparrow and Bitcoin Core descriptor files and single keys, converts them to a descriptor on the vault and shows the result before the check. A new Load File button reads them from the Transfer Drive.

v1.45 — October 15, 2026

Bring a wallet from another app into the Output Descriptor tool as a watch-only wallet, and a much tighter lock-down of SafeKeep OS itself.

  • Import a watch-only wallet — paste or scan the output descriptor from another app (Sparrow, BlueWallet, Bitcoin Core), single-sig or multisig, including nested SegWit multisig sh(wsh(…)). On the Verify tab, Check Descriptor checks the checksum, refuses private keys, and shows the first receive and change addresses worked out from the descriptor. No seed is needed: without one the result is WATCH-ONLY, and with one loaded it still says MATCH or MISMATCH.
  • Use it like your own — Use This Descriptor (watch-only) loads it into the tool, so the Receive panel (show and check addresses), the address list (.csv), the Bitcoin Core export, the QR code and Print PDF all work for it. The PDF leaves out the seed and passphrase rows. A descriptor without the …/<0;1>/* ending gets a warning and can’t be loaded.
  • No terminal, no file manager — release builds no longer include them. The session runs as the system administrator (root), so either one was a way into the whole system.
  • No network drivers — every network, Wi-Fi, Bluetooth, NFC, USB-network (including phone tethering) and USB-gadget driver is deleted from the image, and the build fails if one is left. Compilers, kernel headers and DKMS are removed after the build, so a new driver can’t be compiled on the stick.
  • A network watchdog — if a network interface ever appears, SafeKeep switches it off and shows a red warning across the top of the app. It also warns if the firewall isn’t loaded.
  • Preparing the computer — the stick controls the operating system, not the computer’s firmware, so unplug network cables and turn off Intel AMT/vPro and the wireless radios in the BIOS/UEFI. See Preparing the computer.

v1.44 — October 15, 2026

The multisig builder in the Output Descriptor tool can read a cosigner’s key straight from a Coldcard or Trezor One plugged into the vault by USB.

  • Coldcard (USB) and Trezor (USB) — new buttons on each cosigner. With the device plugged into the offline SafeKeep computer, SafeKeep reads its master fingerprint and its BIP-48 multisig key for the chosen address type (m/48'/0'/0'/2' Native SegWit, /1' Nested SegWit, /0' Legacy) and fills in the cosigner. The key never passes through an online computer, which is especially useful for the Trezor One: it has no SD card or QR code output.
  • Safe by design — a locked Trezor shows the same PIN grid as signing (only grid positions are sent, never the PIN). The import only reads: nothing is paired or saved, and the device isn’t asked to sign. Only the three multisig key paths can be read, and only mainnet keys are accepted.
  • Tested so far — reading from a Coldcard has been tested. Reading from a Trezor One hasn’t been tried on a real device yet.
  • Mix-ups caught early — a device already used for another key is flagged, and a cosigner key for a different address type than the one selected is refused, whether it was read by USB, pasted or scanned.
  • Fix — with Multi-Sig selected, Seed Management’s address note now points to the Output Descriptor tool (it used the old name “The Script”).

v1.43 — October 13, 2026

The PSBT Signer now takes and gives files sent with The Courier, both ways. This is for wallets that only work with files, such as Trezor Suite: no Transfer Drive and no saving files on the vault.

  • In — Scan Unsigned PSBT also accepts an unsigned .psbt file sent with The Courier, either from a computer’s screen or relayed by a phone. Frames are collected in any order, from any point in the loop. Each chunk is checksum-checked, and progress shows as “chunk 5 / 12”. The file is put back together in memory without being saved, and loads exactly like a file from the Transfer Drive. Binary .psbt, base64 and hex text files are accepted; any other file is refused with a clear message.
  • Out — A new File (Courier) export format plays the signed PSBT as a Courier file loop named <name>-signed.psbt. The Courier on your online computer receives it and saves the file for your wallet to open. It’s chosen automatically when the PSBT arrived through The Courier. Wallets that scan QR codes, such as Sparrow, can still use UR or Standard.

v1.42 — October 12, 2026

A new Receive panel in the Output Descriptor tool. It works the address out from your descriptor on the offline stick, so malware on an online computer can’t swap it. The vault has no network access and can’t see which addresses have been used, so the intended workflow is: let your watch-only wallet (for example Sparrow on your own node) pick the next unused address, and use SafeKeep to check it.

  • Show a receive address — pick an address by number with ← and →, starting at 0. The address is shown in groups of four so you can compare every character, with a QR code, a Copy button, and a label giving its number, path, wallet type and key fingerprints. It works for single-signature, Taproot and multisig wallets; a Silent Payment wallet shows its one fixed address.
  • Check an address — paste or scan an address, and SafeKeep searches the wallet’s first 1,000 receive and change addresses. If it’s found, you see “✔ receive address #N” (a change address is flagged as one). If it isn’t, you get a warning not to send to it. It accepts bitcoin: links and uppercase addresses, and refuses addresses with a typo and testnet addresses.

v1.41 — October 12, 2026

  • Export Addresses (.csv) — the Output Descriptor tool can save your wallet’s addresses as a list. Choose how many, from 1 to 10,000, always starting at the first address (index 0), and optionally the same number of change addresses. Each row has the index, chain, path and address, and no keys. Before saving, the first addresses are checked against the ones shown on screen. It works for single-signature, Taproot and multisig wallets, but not Silent Payments, which have one fixed address.
  • Exports go to the Transfer Drive — the Output Descriptor tool’s exports (descriptor .txt, Bitcoin Core .json and the address .csv) now save to the Transfer Drive, ready to send from the Transfer Hub. Before, they were saved inside the encrypted vault, where the Transfer Hub couldn’t reach them. If the Transfer Drive isn’t available, the vault says so and saves nothing, and an earlier export is never overwritten.
  • Multisig builder: no duplicate keys — the same key entered twice is now refused, and the message names the keys. This happens when one cosigner QR code is scanned for two keys, or a cosigner uses the same seed as Key 1. Before, the build reported success, but every verification address showed “error” and wallets like Sparrow read the descriptor as having fewer keys. If you built a multisig descriptor whose addresses showed “error”, build it again.
  • Multisig builder: other improvements — a build whose addresses can’t be worked out now reports an error. Cosigner keys ending in /<0;1>/* or /0/* are accepted. Key 1 (this device) now shows its key origin and xpub, with a Copy button, and updates with the passphrase and address type.
  • Transfer Hub — .csv files on the Transfer Drive are listed and can be sent.

v1.40 — October 11, 2026

  • Courier Tool transmit controls — the controls for sending a file or text by QR now look and work like the online Courier Tool. Choose File (animated QR loop) or Text / password (single static QR) with two cards; the selected one is highlighted in orange. The file picker is a drop zone: click it to pick a file or drop one onto it, and it shows the file’s name and size, with an amber warning only for large files. Density and Speed are sliders that show their current value and what each end means.
  • Nothing else changed — QR transfers work exactly as in v1.39, including between the vault and the online Courier Tool.

v1.39 — October 8, 2026

Better seed generation, a Wallet Record built from your descriptor, and an easier Passphrase Library.

v1.37 and v1.38 came out earlier the same day and are replaced by v1.39. If you installed either, update to v1.39.

  • Verifiable Dice — a new Entropy Generator mode that uses physical dice only. The seed is the SHA-256 of your rolls (exactly 50 rolls for 12 words, 99 for 24), the same method SeedSigner and COLDCARD use, so the same rolls give the same words on either device and you can check one against the other. Mixed mode stays the default.
  • Playing Cards — a new entropy source: shuffle a 52-card deck and enter it from the top. A full deck adds about 225 bits.
  • An honest entropy meter — the meter now counts only the randomness you add: 0.5 bits per mouse sample, and 4 bits per camera frame taken only from the sensor-noise bits. Digital Dice are gone; they came from the same generator that is always mixed in, so they added no security.
  • Wallet Record starts from the descriptor — use the wallet you just built in the Output Descriptor tool, or paste or scan the descriptor from any wallet app (animated QR codes work, such as Sparrow’s wallet export). The vault checks the descriptor’s checksum, refuses private keys, and works out the wallet type, M-of-N, script and first receiving address. If a key is missing its …/<0;1>/* path, it warns you instead of showing an address. You name each key (“Dave’s Coldcard — home safe”) and mark which ones need a passphrase. On the printout, keys appear by name only: for a key with a passphrase, the descriptor’s fingerprint belongs to the seed words plus the passphrase, so it isn’t printed as the key’s identity. You can add the seed’s own fingerprint to the name. The printed layout is otherwise unchanged.
  • Wallet Record fixes — nested SegWit and legacy multisig wallets were recorded as single-signature. If you printed a record for one of these, print it again. Passphrases are also no longer saved in the browser.
  • Passphrase Library — the generator opens right under the passphrase field. A generated passphrase no longer has to be re-typed: instead you check your written copy before saving. Changing the separator or capitalization keeps the same words, and a new Use this wallet now button switches to the passphrase wallet straight away.
  • Passphrase backup fix — Print PDF could show the fingerprint of a different, active wallet. It now always matches the passphrase being printed. If you printed a passphrase backup while another passphrase wallet was active, print it again.
  • Seed XOR — merging now shows the recovered fingerprint to compare with your share cards, and rejects a share entered twice or shares that cancel out to an empty seed. The recovery drill also works in preview mode.
  • SeedQR — Standard SeedQR is now offered alongside Compact, with a note on which wallets can scan each.
  • If you used v1.37 — a Wallet Record made by scanning a wallet QR code (for example a Sparrow multisig export) showed the wrong first receiving address. Discard any record printed that way and print a new one.

v1.36 — October 6, 2026

A release about verification: checking the computer, the dice, the transaction and the release itself.

  • Start-up self-check — before you can enter anything, the vault runs published Bitcoin test vectors (seed words, key derivation, addresses for every wallet type, signatures) through its own code. If this computer gives a single wrong answer, the vault stops with a plain error screen instead of risking a wrong key or address.
  • Safer signing — the vault now refuses any signature type that doesn’t cover the whole transaction (anything other than SIGHASH_ALL), including for Silent Payment inputs. Such signatures could let someone change where the funds go. The review screen explains the block, and Force Sign cannot override it.
  • LifeHash icons — a small coloured pattern drawn from the master fingerprint, on the Dashboard, the tool sidebar and the PSBT Signer. It matches the picture Sparrow Wallet shows for the same wallet.
  • Dice fairness check — the Entropy Generator scores your physical dice rolls and, after 30 rolls, tells you whether the die looks fair, possibly biased or likely biased. It’s advice only and never blocks you.
  • Bitcoin Core export — the Output Descriptor tool exports a watch-only import file for your own Bitcoin Core node, with the commands to load it.
  • Verifiable releases — each app release now comes with a checksum, the maintainer’s signature, a GitHub build attestation and a Bitcoin timestamp, and the app is a reproducible build: rebuilding the release’s source gives byte-for-byte the same file. See how to verify.

v1.35 — October 5, 2026

  • Fee rate on the review screen — the PSBT Signer used to show “? sat/vB” before signing. It now estimates the size the transaction will have once signed and shows a real fee rate. The high-fee guard is unchanged.

v1.34 — October 5, 2026

The largest update so far.

  • Co-sign with a Coldcard or Trezor — pair a Coldcard or Trezor One in Device Options, and the PSBT Signer can ask it for a signature over USB. In a Temporary Session, Sign with Hardware Wallet reviews and signs a multisig transaction with hardware wallets alone, with no seed loaded.
  • A real Lock — locking now closes the app, clears your keys from memory and closes the encrypted partition, returning to the password prompt. It can never power the machine off. Temporary Sessions gained Return to Master Vault.
  • Settings survive a reboot — theme, display scale, sound and the idle timers are saved in your encrypted vault and restored at the next boot. Temporary Sessions never save them.
  • Sound on more laptops — at boot the system unmutes the sound card and sends audio to a USB sound device if one is plugged in, otherwise to the built-in speakers instead of HDMI. Nothing network-related was added.
  • Automatic Transfer Drive — the Transfer Drive mounts by itself, with no buttons or permission prompts.
  • Change-hijack protection — a full review of the wallet’s cryptography against official test vectors found and closed ways a malicious coordinator could disguise a payment as change.
  • Build it yourself — anyone with an x86-64 Linux machine can build the USB image from a fresh clone. See Build It Yourself.
  • A refreshed look — new fonts and icons, tools grouped by purpose, and seed words blurred until you hover over them.
